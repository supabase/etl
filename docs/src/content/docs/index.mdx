**Supabase ETL** is Supabase's open-source Rust framework for Postgres change
data capture. For each published table, it first performs an initial sync of
existing rows. It then replicates changes and delivers them to a
built-in or custom destination. BigQuery is the most mature destination module;
DuckLake, ClickHouse, and Snowflake are also available in `etl-destinations`.

For the managed product in the Supabase Dashboard—including availability,
pricing, and operations—use the
[Supabase Pipelines documentation](https://supabase.com/docs/guides/database/replication/pipelines).

## How It Works

Supabase ETL replicates each table in two phases:

1. **Initial sync:** Copy the existing rows selected by the publication.
2. **Ongoing replication:** Capture subsequent inserts, updates, deletes, and
   truncates, then deliver those changes as ordered [events](/explanation/events/).

Across both phases, a [store](/explanation/traits/) persists checkpoints and
table state so replication can recover safely after a restart.

Continue with the [First Pipeline tutorial](/guides/first-pipeline/), or read the
[architecture overview](/explanation/architecture/) before integrating ETL.
